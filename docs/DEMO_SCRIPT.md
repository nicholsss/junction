# Three-minute recording script

Record only what is actually present. R2283 has not been signed. Arrange the real named human before recording the sign-off portion; never paste prepared answers on their behalf. Open [PR #1](https://github.com/nicholsss/junction26-messagepack-csharp/pull/1) and [the walkthrough](https://nicholsss.github.io/junction/) first.

**0:00–0:20 — Concept.** Open the default Review R2283 view. “Automate repeatable checks and direct human attention to consequential uncertainty. This is a reference, not a finished product.” Point to the pending owner decision. Say the reviewer can decide without reading source; source is optional corroboration.

**0:20–1:00 — Decision brief, not a diff tour.** Stay in normal page text. “The page starts with what the change is for, what the recorded evidence supports, and what remains risky or unknown.” Show that statements are tagged `Harness observation`, `AI interpretation` or `Team explanation` and link to their evidence. Read the derived counts aloud: 2 of 8 AI claims are test-backed; 170 passed of 170 on the patch; 3 failed of 170 on base source, which is the expected, useful result. Say the two-project reproduction was not run. “The counts come from the receipt, not from this page.”

**1:00–1:30 — Risk and reliability together.** Show the suppression risk: the patch drops diagnostics located outside the current compilation, and a local crash-only comparison still reports two `MsgPack004` errors that the patch hides. Point out that the comparison is our hand-applied approximation, not the reference patch. Then show the claim-classification section. “Test-backed is an evidence link, not proof. Contradicted and unsupported are not hallucination verdicts. There is no trust score.” Expand only if asked.

**1:30–2:00 — Judgment, not a questionnaire.** Show REF1/REF2 with their recorded positions, OOR1/OOR2 with accept scope / change required / needs owner judgement, and UNK1/UNK2 acknowledgements. Nothing is preselected. “Accept needs an acceptance-compatible position for both questions, both findings, and both unknowns. Request changes and escalate need only my reason.” Do not choose for the human. If a structured position requires changes, show that acceptance stays blocked and explain why.

**2:00–2:35 — Real human action, only if it happens.** The named human reads the brief and posts their own `/receipt accept`, `/receipt changes` or `/receipt escalate` comment with the full Head SHA, their own reason and any structured lines. The operator runs `python3 engine/pr.py decide 1 --human LOGIN --name 'Name'` (same-account flag only if applicable and disclosed). Show the resulting status and persisted receipt, push main and run `python3 engine/publish_pages.py`; reload the page. Accept maps to success; changes to failure; escalation stays pending owner judgement. If no human decides, show pending and say this step remains unperformed.

**2:35–2:50 — Changed head, only if deliberately demonstrated.** After a real decision, a new push loses the old SHA's successful receipt status. Run `decide` again to show pending and the stale explanation. A changed head needs fresh checks. Do not pretend this already happened: the current evidence is mocked tests of stale handling, not a performed push/sign-off sequence. Prefer showing those tests if the prepared change must remain pinned.

**2:50–3:00 — Optional source and measurement.** Expand **Optional implementation evidence** only now. “This is corroboration, not the decision path. A missing or stale snapshot hides only this panel.” Close it and end on the historical measurement: five injected bad claims held from verified; the live run is separate at two of eight test-backed. “One repository, one machine, no human time study. Neither number is a defect-detection rate. Production event automation and required-status branch protection are not built.”
